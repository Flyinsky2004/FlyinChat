====================
1. 结论摘要（先看这个）
====================
1) /init 的定位不是“普通问答命令”，而是“项目初始化工作流入口”。
2) 它的目标是为当前仓库生成/更新项目级记忆文件（通常是 CLAUDE.md），把项目约束显式化。
3) /init 使用的不是单一固定 prompt，而是“专项子系统 prompt + 主会话提示词上下文”的组合。
4) 已公开资料能确认 /init 属于专项 prompt 体系；但“完整原始 prompt 文本”在公开教程中未完整披露。
5) 因此最可靠做法是：基于已知行为复刻一个等价初始化提示词管线，而不是执着于逐字还原。

====================
3. /init 在架构里的实现思路（机制级）
====================
3.1 触发路径（概念）
用户输入 /init
-> 命令系统识别为 slash command
-> 路由到初始化处理器
-> 组装初始化上下文（项目结构、Git 状态、已有 CLAUDE.md/记忆）
-> 使用专项初始化 prompt 调模型
-> 产出结构化项目说明
-> 写入或更新 CLAUDE.md
-> 将结果回到主会话

3.2 它与普通聊天的差异
- 普通聊天：目标是回答问题。
- /init：目标是“生成长期可复用的项目工作约束”。
- 普通聊天主要产出文本。
- /init 典型产出是“文件变更 + 规则沉淀”。

3.3 它与 /memory 的关系
- /init：第一次建档/初始化。
- /memory：后续维护与增量更新。
- 两者共同服务“项目记忆治理”。


====================
4. /init 用到的提示词：已知事实与合理推断
====================
4.1 已知事实（可直接确认）
1) Claude Code 提示词是分层装配，不是单段固定文本。
2) /init 属于“专项子系统 prompt”之一。
3) 初始化目标聚焦项目说明、运行方式、命令、规范、协作约束等。

4.2 合理推断（工程复刻所需）
/init 的最终有效提示词大概率由下列部分组成：

(1) 基础系统层
- 你是工程任务代理
- 输出要准确、结构化、可执行

(2) 会话动态层
- 当前工作目录/仓库信息
- Git 状态（分支、最近提交、工作区）
- 用户语言与风格偏好

(3) 初始化专项层（/init 核心）
- 任务：为本项目生成 CLAUDE.md（或更新）
- 内容要求：项目结构、启动/测试命令、编码规范、协作约束、风险提示
- 输出格式要求：markdown，分节清晰，可直接落盘

(4) 工具策略层
- 必须先读项目关键文件再生成
- 不确定项标注 TODO/待确认，不编造命令


====================
5. 为什么很难拿到“逐字原文 prompt”
====================
1) 提示词是动态拼装的，多段来源并受运行状态影响。
2) 不同版本可能改文案，但机制不变。
3) 公共教程通常展示机制与片段，不一定公开完整模板。

实践建议：
- 关注“职责与结构”，不要过度依赖逐字文案。
- 做可观测的初始化链路（输入来源、产出质量、回滚）。


====================
6. 可直接复刻的 /init 提示词模板（建议稿）
====================
下面是等价实现模板，可直接用于你的系统：

【System - Init Specialist】
你正在执行项目初始化任务。目标是为当前代码仓库生成或更新一份 CLAUDE.md，作为后续 AI 协作的项目约束文档。

要求：
1. 先基于已读取的仓库事实再写，不得凭空编造命令或技术栈。
2. 内容必须覆盖：
   - 项目简介与目标
   - 目录结构与关键模块
   - 安装/启动/测试命令
   - 代码规范与提交约定
   - 常见风险与禁止事项
   - 推荐工作流（如先计划后改动）
3. 信息不确定时，明确标注“待确认”，并给出建议确认方式。
4. 输出为可直接保存的 Markdown。
5. 保持简洁、可执行、可维护。

【User - Init Task】
请根据当前仓库上下文，生成（或更新）CLAUDE.md。若已存在旧版，请保留有效规则并做增量改进，避免无关重写。


====================
7. /init 最小实现蓝图（给 AI Agent）
====================
Step 1: 命令路由
- 在 slash command registry 注册 /init。

Step 2: 上下文采集
- 读取仓库根目录结构
- 读取 README、package/pyproject、测试配置、lint 配置
- 采集 Git 简要状态
- 读取现有 CLAUDE.md（如存在）

Step 3: Prompt Assembler
- base_system + dynamic_context + init_special_prompt + user_task

Step 4: 生成与落盘
- 调模型产出 markdown
- 写入 CLAUDE.md（先备份再覆盖）

Step 5: 校验
- 最小校验：是否包含必需章节
- 命令校验：命令字段非空且语法看起来合理

Step 6: 回传结果
- 告知新增/更新内容摘要
- 标注待确认项


====================
8. 验收标准
====================
1) /init 在空仓库与已有 CLAUDE.md 两种场景都可运行。
2) 生成文档覆盖“结构、命令、规范、风险、工作流”五类信息。
3) 不确定信息被明确标注，不出现硬编造。
4) 重复执行 /init 时具备幂等性（增量更新优先）。
5) 失败时可回滚到旧版 CLAUDE.md。

====================
10. 一句话结论
====================
/init 的本质是“项目记忆初始化流水线”，其核心价值在于把隐性协作经验显性化为 CLAUDE.md；提示词是分层组合而非单段秘笈。
